# 客户文件详细审阅规则

目标是证明客户提供的信息已被完整、准确地纳入诊断，避免因只读摘要、首页或少量搜索命中而遗漏关键证据。这里的“完成”是可复核的覆盖状态，不是主观声称“看过了”。

## 逐文件登记

收到文件后立即在 `source/customer-file-index.csv` 建立一行，记录 `artifact_role=reference_document|diagnostic_evidence|mixed`、原始名称、临时保存路径、SHA-256、格式、大小、收到时间、客户说明和与症状的可能关系。重复文件也保留记录并用哈希标明相同；替换版本不得覆盖旧文件。

参考文档用于建立型号、版本、能力或命令语义。在 `triage|deep` 中核对元数据、目录、适用性和当前问题相关章节即可，完成状态为 `reference_complete`；不要把它强行按故障日志逐页审计。诊断证据用于证明现场状态，继续执行下面的完整覆盖。`mixed` 文件分别适用两套规则。

先确认文件能否完整打开、是否加密/损坏、页数或数据范围是否合理。压缩包要列出内部文件清单并逐项登记；嵌套附件、图片、批注、隐藏工作表和导出文件中的多个日志也属于阅读范围。

## 按格式检查完整范围

- **PDF/Word/演示文稿**：确认总页数/幻灯片数，逐页检查正文、表格、页眉页脚、脚注、批注、图例和嵌入对象。布局承载含义时同时做文本提取和页面渲染检查；OCR 结果必须回看原图确认关键型号、端口、错误码和数值。
- **电子表格/CSV**：列出每个工作表，包括隐藏表；检查表头、单位、筛选/隐藏行列、公式与显示值、错误单元格、日期时区、重复项和空缺。不得只读取活动工作表或可见区域。
- **日志/文本/配置**：识别编码、起止时间、时区、日志级别、轮转/截断迹象和配置层级。配置要覆盖全部 section、注释、禁用项及重复键；日志要对完整时间范围做解析/统计/异常检索，并回读每个关键命中前后的上下文。
- **截图/照片/录屏**：使用原分辨率检查整个画面和时间轴，记录设备、端口、LED、菜单路径、选中状态、错误码和时间；不要根据缩略图判断。录屏需覆盖关键动作前后，记录准确时间点。
- **拓扑图**：逐节点和逐链路核对型号、端口方向、线缆类型、VLAN/交换机和信号流；把图中的连接与客户描述及设备发现结果交叉验证。
- **抓包/诊断导出**：确认采集接口、过滤条件、起止时间、丢包/截断状态和协议范围；先做全局会话/错误/重传/时序统计，再围绕故障时间检查相关流。过滤后的视图不能冒充完整原始捕获。

不支持的专有格式必须说明限制，并向客户请求原生查看器可读导出、无密码副本或通用格式。不得从无法读取的内容推断结论。

当 XLSX 因元数据、样式或库兼容问题无法由高层库打开时，不要立即宣布整份文件不可读，也不要修改原件。把副本当作 ZIP 检查 `[Content_Types].xml`、`xl/workbook.xml`、关系文件、`sharedStrings.xml`、样式和各 worksheet XML，恢复可读单元格、公式、工作表名称与隐藏状态；同时记录丢失的格式、批注、图表或无法解析内容。只有底层包也损坏或关键内容无法恢复时才标记 `blocked`。

## 大文件的可靠覆盖

大文件不要求模型逐字把全文装入上下文，但要求分析覆盖整个文件：

1. 取得总行数、页数、时间范围、工作表或数据分区。
2. 检查开头、结尾、结构变化、缺口、轮转和异常密集区。
3. 对全范围运行与症状相关及通用故障信号的解析/统计/检索。
4. 回读每个关键命中的上下文，并检查支持与反证。
5. 在审阅记录中写清自动分析范围、人工细读范围及未覆盖部分。

仅运行关键词搜索、只取前/后若干行或只让模型生成摘要，不满足完成条件。

## 交叉核对与完成条件

对每个文件在 `customer-file-review.md` 记录：

- 可核对的总单位与已检查单位；
- 关键事实及准确定位；
- 与客户描述、其它文件、官网资料或设备响应一致和冲突之处；
- 对分类、查询选择和风险判断的影响；
- 无法读取、缺失、截断或可信度不足的内容。

只有所有文件满足各自角色的审阅要求后，案件级状态才设为 `complete`：参考文档为 `reference_complete|complete`，诊断证据和 mixed 文件为 `complete`。没有文件为 `none_provided`。高影响诊断证据无法可靠读取时为 `blocked`，不得继续形成初始分类或确认根因。
