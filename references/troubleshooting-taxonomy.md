# IPAV 故障分类参考

本参考把用户提供的《IPAV product Troubleshooting》思维导图转成可执行的分类规则。它只用于故障归类和检查方向，不是设备 API 命令文档，也不授权执行任何写操作。

## 分类顺序

1. 先完成 `intake.md` 和 `user-actions.csv`；未知信息必须显式标记。
2. 根据主要受影响功能和当前最强证据选择一个主分类；需要时添加次分类。
3. intake 完成后的第一次分类标为 `provisional`。设备证据收集后改为 `confirmed` 或 `inconclusive`。
4. 同一症状可落入多个分类。例如“马赛克”既可能是视频表现，也可能源于网络；用主分类表示当前最有证据的故障域，用次分类保留跨域可能性。

## PDF 中的五类

### `power` — 电源问题

典型方向：DC 电压/电流规格、供电指示、PoE 交换机配置与功率预算、网线类别/长度/屏蔽、接地电位差、雷击或静电损伤。

### `audio` — 音频问题

典型方向：模拟音频静音/音量/信源/配对/格式，HDMI 音频静音、PCM/LPCM/Dolby/DTS、ARC/eARC，以及 Dante 交换机配置和控制器配对。

### `video` — 视频问题

典型症状：黑屏、无信号、雪花点、马赛克、HDCP 失败、延迟过高、闪屏和色偏。典型方向包括显示器待机/通道、HDMI 线、TX/RX 配对、交换机与丢包、切换/缩放/帧率/Genlock、色彩空间和 EDID。

### `network` — 网络问题

典型症状：画面卡住或马赛克、设备频繁上下线、无法发现设备。典型方向包括组播地址与转发/过滤、IGMP、级联、巨帧、IP 地址冲突、网络环路和防火墙限制。

### `control` — 控制问题

典型症状：控制器发现不到 TX/RX、RS232、USB 或 IR 失效。典型方向包括防火墙/IP/IGMP Snooping、RS232 端口/波特率/工作模式/配对与硬件限制、USB hub 层级/端点数量/Host-Device 模式/配对，以及遥控器电池、距离和 IR 配对。

## 新增的两类

### `protocol_conflict` — 协议冲突

当证据指向两端标准、版本、角色、格式、时序或协商能力不兼容时使用。例：HDCP 版本不匹配、EDID/色彩/时钟或帧率协商冲突、ARC/eARC 或音频格式不兼容、RS232 参数/工作模式不一致、USB Host/Device 角色冲突。

不要仅因出现“IP 地址冲突”就归入本类；该项按 PDF 属于 `network`。普通线缆损坏、设备离线或尚未查明原因也不能直接称为协议冲突。协议冲突通常同时附加受影响域作为次分类，例如主类 `protocol_conflict`、次类 `video`。

### `other` — 其它原因

仅在其余六类均不能合理解释主要问题，或证据明确指向分类表外的机械、环境、第三方应用/平台或人为流程原因时使用。必须列出排除过的候选分类和证据。单纯信息不足时仍应选最符合症状的低置信度暂定分类，或将分类状态标为 `inconclusive`，不得无说明地塞入本类。

## 置信度

- `high`：有可重复现象和直接设备/日志/测量证据，关键反证已检查。
- `medium`：症状与多项证据一致，但仍有一个重要替代解释未排除。
- `low`：主要依赖用户描述、时间关系或间接迹象；需明确下一条最小验证动作。

分类记录至少包含：时间、主分类、次分类、状态、置信度、用户陈述、相关操作、支持证据、反证、排除项、仍缺信息和下一步验证。

## 独立诊断维度：公开参数、固件 UI、运行态与持久化状态

以下是诊断维度，不是新增分类。症状尚未定位时仍按受影响功能选择主分类；只有受控证据明确指向设备内部持久化配置/状态时，最终主类才可使用 `other`，并把受影响域列为次类。

- `visible_parameter_state`：静态 API 手册或其它公开接口能直接查询的参数层。
- `firmware_exposed_parameter_state`：设备同固件 Web UI 暴露、但静态 API 文档遗漏的主开关、模式或状态。公开参数全为默认值但症状仍存在时，应核对静态命令集与固件 UI 实际读取字段；不能直接跳到内部存储损坏。
- `volatile_runtime_state`：服务、缓存、临时会话或易失状态；软重启后消失可作为支持证据，但不单独证明根因。
- `persistent_internal_state`：公开参数与可靠基线一致、软重启无效、问题随设备而非外部链路迁移，并在受控工厂复位/最小配置后消失时才提高置信度。

工厂复位恢复正常不能自动写成“存储区损坏”。它也可能清除了隐藏配置、旧缓存、无效组合或未暴露状态。根因粒度必须与证据相称，并保留替代解释。
