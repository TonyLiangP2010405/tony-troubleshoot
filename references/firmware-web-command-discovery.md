# 固件 Web UI 命令发现与安全分级

本规则用于静态 API 手册可能落后于设备固件、某些主开关或状态仅由设备自身 Web UI 使用的情况。目标是补齐只读可见性，不是把前端字符串自动变成可执行 API。

## 被动证据顺序

1. 记录准确型号、硬件版本、固件版本、Web UI 构建版本和访问时间。
2. 使用客户授权的正常登录或现有认证会话；不绕过认证、不猜密码、不禁用安全控制。
3. 保存设备自己提供的 HTML/JS/CSS 资源哈希，在副本中搜索当前症状相关 UI 标签、命令枚举和调用点。
4. 被动观察页面初始加载、打开只读状态页或正常刷新产生的 WebSocket/HTTP 请求与响应。不要点击 Apply、Save、Pair、Reset、Upgrade 或其它可能写入的控件来发现协议。
5. 将固件观察结果与静态 API 文档和本地 IPAV/ODM 资料逐条比较，写入 `command-source-audit.csv`。

## 安全分级

- `documented_readonly`：适用静态文档明确只读，可按原规则执行。
- `firmware_observed_readonly`：同型号同固件 UI 在同一传输上自动发送该准确请求以读取状态；保存了调用点、请求、响应和无写入交互的证据。仅允许相同传输、相同参数形态的最小重放。
- `enumerated_unverified`：只在 SPA 字符串、枚举或未执行代码中出现。不能执行；命令名含 `GET` 也不改变该结论。
- `mutating_or_unknown`：SET/Apply/Save/Pair/Reset/Upgrade，或行为/参数不明。只登记；执行需准确语义、影响与回退，并获得具体授权。

WebSocket 观察不能推导 Telnet、SSH 或 HTTP 也支持相同字符串。若确需跨传输验证，必须另有该传输的文档或同固件被动行为证据。任何未知响应、设备重连、状态变化或异常负载迹象都要立即停止。

## 命令集差异输出

每行记录命令、来源、固件、传输、静态文档是否存在、本地知识库证据、UI 枚举位置、被动调用证据、只读依据、验证状态和允许范围。静态文档缺失但满足 `firmware_observed_readonly` 的命令可以加入诊断目录；报告必须标注它不是静态 API 手册覆盖项。

写命令仍遵守逐项授权：说明准确目标、当前值、拟改值、预计影响、恢复方式和验证方法。Web UI 登录凭据、Cookie、授权头和握手秘密只在内存或现有会话中使用，所有持久证据必须脱敏。
